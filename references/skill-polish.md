# 技能描述规范与润色（《三国杀官方规则集》全量流程）

回链：[SKILL.md 开始前](../SKILL.md)、[§2 先拆规则](../SKILL.md)、[§8 翻译、描述与素材](../SKILL.md)。本规范整合自 `sgs-skill-polish`，依据凌天翼《三国杀官方规则集》，把技能描述落成**无歧义、可结算、官方风格**的文本。核心信条：**描述即规则**——一行描述里的每个字（可／需／须、时／后、弃置／交给、你／其）都对应确定的结算行为，措辞含糊等于实现时会做出两套不同的技能。

## 1. 判定任务类型

| 类型 | 用户输入特征 | 走的流程 |
| --- | --- | --- |
| A 起草 | 只有设计意图／白话描述，没有成文描述 | 流程 A：拆意图 → 选模板 → 成文 |
| B 改写 | 已有描述，要“优化／润色／规范化／改成官方风格” | 流程 B：逐句对照规则集改写 |
| C 审查 | 已有描述，要“找茬／查漏洞／查歧义／查平衡” | 流程 C：按第 6 节清单逐项过 |

同一份描述可能先 C 后 B。开始前明确告知走的是哪个流程。做新武将时，通常在写码前走流程 A 或先 C 后 B，把六要素和无歧义描述拍板后再落成 Lua。

完成标准：任务类型已声明，原描述已逐字读取（用户给图时先放大确认原文，形近字当面问）。

## 2. 六要素拆解（所有流程共用）

把每个技能拆成六要素表，缺哪项补哪项。**状态类技能无时机**，其余触发类技能六项俱全：

| 要素 | 说明 | 描述中的呈现 |
| --- | --- | --- |
| 时机 | 技能何时能发动 | “结束阶段开始时”“当你受到1点伤害后” |
| 条件 | 发动需满足的状态 | “若你没有手牌”“若此牌为红色” |
| 发动角色 | 谁发动 | 几乎总是“你”（=技能拥有者）；他人视角写“其” |
| 目标 | 指向谁／什么 | “选择一名其他角色”“选择你攻击范围内的一名角色” |
| 消耗 | 发动时先执行的单个操作 | “你可弃置一张牌▶” —— **一个技能最多一个消耗，不存在双消耗** |
| 效果 | 消耗之后发生什么 | ▶之后的内容 |

拆解时同步回答：这是触发技／主动技／锁定技／状态技／觉醒技／限定技／主公技／转化技？标签决定句式（见第 4 节模板）。多效果考虑 ①② 拆成独立技能。

完成标准：每个技能都有六要素表；意图与原描述不一致处已列出。

## 3. 核心用词规则（改写时逐条对照）

这些是规则集的硬性规定，[速查手册](速查-用语与符号.md)有完整版：

1. **“可”决定一切可选性**：锁定技≠必须发动。有消耗的技能，消耗前的“可”=可选择发动；效果前的“可”=可选择执行。无消耗技能唯一效果前的“可”=可选择发动。删除或添加“可”前必须确认设计意图。
2. **时机命名精确**：阶段时机只有五种合法写法——“X阶段开始前 / X阶段开始时 / X阶段 / X阶段结束前 / X阶段结束时”。技能标注“出牌阶段”=出牌阶段内的空闲时间点。事件时机=“当……后 / ……时 / ……前”，如“当你受到1点伤害后”（若无对应区别理由不写“受到伤害时”）。时机用词分两层方言：规则集方言把回合级细分为“回合结束前❶~❻”（不出现裸的“回合结束时”），官方游戏内文本用“每回合结束时”等粗粒度写法——DIY 卡面默认后者，语义边界查规则集（速查·3.3）。
3. **操作动词不可混用**：
   - “A令B弃置一张牌”=**B**选牌；“A弃置B的一张牌”=**A**选牌
   - “获得”=主动操作；“得到”=结果性陈述
   - “交给”的牌必须是使用者拥有的；“观看”≠“展示”≠“亮出”
   - “无效”≠“取消”≠“防止”≠“无视”（规则集 V2.2 用语章各有定义）
4. **数值有公式保护**：距离、攻击范围、手牌上限用“X为……”或 max{} 保护下限（距离／攻击范围下限 1，手牌上限下限 0）；“等量的”必须能明确指到前一个非固定数量；“一半”=向下取整。
5. **造成伤害≠失去体力**：失去体力无来源、无奖惩。设计意图是“掉血但不追究来源”时用失去体力。
6. **标记先定义**：技能中出现的标记必须在首次出现处定义——“……置于武将牌上（称为‘权’）”。引用时用引号：X为“权”数。
7. **合法性表述**：选目标写“能……的”（有能力约束）或“……的合法目标”（规则约束），不得混用。
8. **变量定义位置**：“（X为……）”单处使用紧跟首次出现（〖权计〗式）；多处使用放整句末、句号之后统一覆盖。两种都是官方惯例，位置不影响结算；句末版不要粘在最后一个分句与句号之间（会被误读为只定义该分句）。

## 4. 结构模板（官方原文范例）

改写时套用最接近的官方句式。以下均为 V1.0 配套卷卡牌章原文：

**纯触发、无消耗**：
> 〖闭月〗——结束阶段开始时，你可摸一张牌。

**主动技，消耗▶效果**：
> 〖制衡〗——出牌阶段限一次，你可弃置至少一张牌▶你摸等量的牌。

**延时类效果（→跳过阶段后补操作）**：
> 〖放权〗——出牌阶段开始前，你可跳过此阶段▶此回合结束前❶，你可弃置一张手牌并选择一名其他角色。若如此做，其获得一个额外回合。

**判定型分支**：
> 〖刚烈〗——当你受到1点伤害后，你可判定。若结果为：红色，你对来源造成1点普通伤害；黑色，你弃置来源的一张牌。

**状态技（锁定、无时机）**：
> 〖空城〗——锁定技，若你没有手牌，你不是【杀】和【决斗】的合法目标。

**标记+数值修正（①②拆分）**：
> 〖权计〗——①当你受到1点伤害后，你可摸一张牌▶你将一张手牌置于武将牌上（称为“权”）。②你的手牌上限+X（X为“权”数）。

**转化技（改实体牌选择标准）**：
> 〖武圣〗——当你声明使用或打出普【杀】时，你可将此【杀】对应的实体牌的选择标准改为你的一张红色牌。

**多目标约束（复杂主动技的极限写法）**：
> 〖离间〗——出牌阶段限一次，你可弃置一张牌并选择一名能使用无对应的实体牌的【决斗】的男性角色A和一名是A使用无对应的实体牌的【决斗】的合法目标的男性角色B▶A对B使用无对应的实体牌的【决斗】。

**觉醒技**：
> 〖志继〗——觉醒技，准备阶段开始时，若你没有手牌，你选择：1.回复1点体力；2.摸两张牌。你减1点体力上限，获得〖观星〗。

**主公技**：
> 〖救援〗——主公技，锁定技，其他吴势力角色对你使用的【桃】回复的体力+1。

**目标转移（含合法性括注）**：
> 〖流离〗——当你成为【杀】的目标时，你可弃置一张牌并选择你攻击范围内的一名是此【杀】的合法目标的角色（距离关系限制规则对此次合法性检测不产生影响）▶此【杀】转移给该角色。

**改规则型**：
> 〖羽化〗——锁定技，你将你弃牌阶段的弃牌规则改为：若你的基本牌数大于你的手牌上限，你弃置X张基本牌（X为你的基本牌数与你的手牌上限之差）。

**距离修正**：
> 〖马术〗——锁定技，你至其他角色的距离-1。

套用原则：结构向官方模板靠拢，内容忠于用户设计意图。找不到同类官方范例的新机制，用最朴素的“时机+若+可／需+操作”句式写，并在边界情况备注里说明这是规则集未覆盖的自创结构。

## 5. 流程

**输入形态与写回约定**（所有流程共用）：技能原文可能来自纯文本、图片（先放大逐字确认，形近字当面问）、Lua 翻译表或卡面 JSON（如 FreeKill 拓展、`新UI.*.json` 卡面模板）。JSON／Lua 输入先用只读方式定位并提取技能描述字段（不改文件），改写经用户确认后再写回——只改描述文本字段，不动其余结构，保持原编码；写回前说明改了哪些字段。

**查证纪律**：凡“官方从不／官方一律”式判断，先查证再落笔——grep 配套卷 PDF 统计句式实际用法，或对照本机官方包／规则集原文。技能名的形近字（悬／疑、矢／死）以用户确认为准，不当面猜。

### 流程 A：起草
1. 让用户给设计意图（触发时机、强度预期、想模仿的官方技能）
2. 六要素拆解（第 2 节）
3. 选模板（第 4 节），起草规范版描述
4. 自查（第 6 节），输出（第 7 节）

### 流程 B：规范化改写
1. 逐字读原描述，六要素拆解
2. 用一两句话向用户复述机制模型（谁对谁、各欠什么、何时终止），有岔路一次问完——强制／可选不能靠主题推断（无“可”的非锁定技：标锁定技还是加“可”，强度不同）
3. 逐句对照第 3 节用词规则和速查手册，列出问题清单（每条注明违反的规则）
4. 最小改动成文，**修字不修骨**：只修主语错位、指代不唯一、条件与分支矛盾等客观错误；作者刻意设计的紧凑句式（如“你发动〖本技能〗”自指再发动，官方有先例）先确认再动，不用显式重构替代
5. 改动对照表呈现（原句 → 新句 → 理由）；用户要求字数更少时按速查〈缩字手段〉压缩，净增减如实报告并逐条给理由
6. 自查（第 6 节），输出（第 7 节）

### 流程 C：审查
1. 逐字读描述，按第 6 节清单逐项检查
2. 对每处歧义，写出两种可能的结算结果（证明歧义真实存在）
3. 对每个结算漏洞，描述具体场景（什么配置下会出问题）
4. 只报问题不改文；用户确认后转流程 B

## 6. 自查清单（成文后逐项过）

1. 时机用词是五种阶段时机／事件时机规范写法之一？
2. “可”的位置正确？（发动可选 vs 执行可选，见第 3 节第 1 条）；非锁定技全文无“可”时，强制／可选是否已经用户确认？
3. 有消耗技能用 `▶` 分隔，且只有一个消耗？
4. 操作动词精确？（谁选牌：弃置 vs 令…弃置；获得 vs 得到；交给的来源）
5. 数值有下限保护？距离／攻击范围最小 1、手牌上限最小 0；“等量”有明确前置量；“一半”注明向下取整（若歧义）
6. 牌名 `【】`、技能名 `〖〗`、标记带引号定义（称为“X”）？
7. “你”=“技能拥有者”无歧义？他人动作用“其”并指代清楚？
8. 目标约束用“能……的”／“……的合法目标”，攻击范围／距离限制写清？
9. 边界：无牌可弃、无合法目标、X=0、目标死亡、伤害为 0、牌不够摸时描述是否自洽？
10. 多效果是否应 ①② 拆分？拆分后各半是否独立成立？
11. 与同武将其他技能无同名／联动冲突？标记转移、技能失去后残留状态处理了吗？
12. 全文读一遍：一个懂规则但没看过设计笔记的人，能否只凭这行描述正确结算？

## 7. 输出格式

只做描述起草／润色／审查时按此结构输出（全部给出，除非用户只要其中一部分）；在完整做武将流程中，则在进入写 Lua 前输出给用户拍板：

```text
### 〖技能名〗
规范版：……（官方风格成文，可直接用作卡面文字）

六要素：时机=…；条件=…；目标=…；消耗=…；效果=…
（状态技注明“无时机”）

改动对照（流程 B/C 后才有）：
| 原句 | 改为 | 理由（对应规则集条款） |

边界情况备注：
- ……（参考规则集“凌天翼按”注解风格，写清结算顺序、特殊情形）

通俗版（可选，用户要时给）：OL 式白话，一句表述，不作结算依据。
```

## 8. 落入 FreeKill 翻译表与 Lua 实现的适配

- **六要素直接映射 Lua**：时机对应 `fk.TurnStart`、`fk.TargetConfirmed` 等触发点；消耗对应 `on_cost`／`card_filter`；效果对应 `on_use`；边界情况备注直接决定边界分支校验。
- **Lua 翻译键 `:[技能]` 适配**：
  - 描述用双引号包裹时，标记名用中文引号 `“权”`（或转义 `\"权\"`），不要裸写英文双引号破坏 Lua 语法
  - 多段效果在 `①②` 前加 `<br/>` 换行
  - 锁定技前缀不要手动加粗；用户明确要求去掉“觉醒技，”等前缀时照做（见 [翻译与素材](text-and-assets.md)）
  - 技能能转手时，需要原持有者执行的句子直接写武将名（见 [技能形态](skill-mechanics.md#技能转手后的措辞)）
