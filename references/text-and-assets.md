# 翻译、描述与素材

回链：[SKILL.md §8 翻译与描述](../SKILL.md)。写翻译表和技能文案、放原画语音时读这一份。

## 翻译表必须覆盖的键

武将名、称号、设计者／配音／画师、阵亡台词、技能名、技能描述，以及所有 prompt。缺一条的表现是界面上空白或直接显示内部名。

```lua
Fk:loadTranslationTable {
  ["<前缀>"] = "角标字",
  ["<前缀>__<真名>"] = "武将名",
  ["#<前缀>__<真名>"] = "称号",
  ["designer:<前缀>__<真名>"] = "设计者",
  ["cv:<前缀>__<真名>"] = "配音",
  ["illustrator:<前缀>__<真名>"] = "画师",
  ["~<前缀>__<真名>"] = "阵亡台词",
  ["<前缀>__<技能>"] = "技能名",
  [":<前缀>__<技能>"] = "技能描述",
  ["#<前缀>__<技能>-active"] = "主动技按钮提示",
}
```

## 文案规则

- 技能名 ≤2 字，称号 ≤7 字；超过会让界面错位
- 锁定技提示不要手动加粗
- 描述支持 `<br/>` 换行；卡面排版要分行就在 ①② 前加
- 用户明确不要“觉醒技，”之类前缀时照做：那是惯例，不是引擎要求
- 带数字的 prompt 用 `%arg` 占位，并把值拼在 `"#技能:::"` 之后；`"#技能:" .. n` 缺占位符会让客户端把 `x` 当变量名直接显示成乱码
- 主动技必须补 `prompt` 翻译，否则按钮提示为空

## 交换两个技能的显示名

先列出“内部技能名 → 显示名 → 效果描述／prompt”的映射。只改用户要求交换的显示标签，保持描述和 prompt 仍与各自实现一致。

不能把内部技能名、武将注册引用和效果代码一起对调。完成后回读 `General:addSkills` 顺序与所有相关翻译键，分别核对代码顺序和实际界面顺序。

## 规则改动后回核描述

描述与实现冲突时以代码为准。逐句把描述对到具体代码行，重点核三处最容易漂的地方：

- X 的上限口径：两边是否同一把尺子
- 计数发生在声明还是支付之后
- 失去技能后债务与标记还收不收回

措辞规范化（把口语化描述改成规范术语）属于可选流程：先只列问题并每条给出两种可能结算，等用户拍板后再出规范版，最后只改 `:技能` 字符串。不要自己在卡面里造术语，例如把“空勾玉”直接写进描述，应落成“体力上限与体力值之差”。

## 原画

路径 `packages/<包名>/image/generals/<代码名>.jpg`，官方将面 250×292。收到其他比例先看构图再裁切缩放，保留脸部和关键道具。

从整卡图裁原画时，把体力图标、势力徽章、技能文案区全部裁掉——这些是游戏运行时自己叠加的，烙进图里会重影。

## 语音

技能音放 `audio/skill/`，阵亡音放 `audio/death/`，文件名按技能和武将代码名匹配（`<前缀>__<技能>1.mp3`），台词文本写进翻译键 `$<前缀>__<技能>1`。

## 不改官方素材

需要覆盖官方资源时，用 `resource_pak/<名字>/` 按原相对路径同名覆盖，不要直接改官方包里的文件。

## 完成标准

素材路径、文件名、尺寸、编码已检查；没有误放进另一份安装。
